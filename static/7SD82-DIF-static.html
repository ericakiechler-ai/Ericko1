Configuration checks

Local onlyOne test set at end A with the remote device quiescent. Reachable: the local measurement path, 87L minimum pickup, every backup function, and all the binary work. NOT reachable: the differential slope, through-current stability, CT ratio and polarity agreement between the ends — the things a differential scheme actually fails on. Plan a loop-back or an end-to-end visit for those, and mark them untested on the record until then.
CT star points agreeBoth ends point line, so a through condition subtracts as it should.
Charging current is significantAt 0.0417 pu the line's charging current is a real fraction of a typical differential threshold. It shows up as a standing differential on a healthy energised line unless compensation is set and correct. On a 15 km cable that is expected — see the charging-current function.

No channels hereNothing on this function is driven from the analogue outputs. It is read from DIGSI and from the link itself, and its evidence is the device's own measurements and event record. The channel table is deliberately empty.
SynchronisationPing-pong synchronisation infers the time offset from the round trip and assumes the path is symmetric in both directions. Method

How this tool arrives at its numbers

Everything below is stated so the arithmetic can be checked by hand. It does not replace the device manual, the DIGSI 5 parameter set or the scheme drawing — it replaces the conversion between them and the test set.

The thing that makes this device different

A differential scheme is two devices, two CT sets and a link. Almost everything that goes wrong in service is a disagreement between the ends — a reversed CT, a ratio entered at one end and not the other, an asymmetric communication path — and none of it is visible from one station. What a test proves depends on how the ends are staged, which is why staging is a setup field here and not an afterthought:

  • Local end only. One test set, remote quiescent. Reaches the local measurement path, 87L minimum pickup, the backup functions and all the binary work. The operating point can only move along Idiff = Irest, so the slope is untestable and so is everything about the far end.
  • Loop-back. The interface looped at the local end. Reaches the slope and proves the link hardware, but the remote device is not in the loop, so remote ratio and polarity stay unproven.
  • End to end. Two time-synchronised test sets. The only staging that proves the whole scheme. Both sets need a common reference — GPS or IRIG-B — because the differential compares samples and an unsynchronised pair produces a phase error that looks exactly like a relay fault.

Differential quantities

both end currents taken positive INTO the line I diff = | IA + IB | I rest = | IA | + | IB | (selectable) per unit: 1 pu = 600 A primary = 1.0000 A at end A, 1.0000 A at end B

To place the device at a chosen point on the characteristic, the two end currents follow directly from the restraint definition. For the sum form:

| IA | = (I rest + I diff) / 2 | IB | = (I rest − I diff) / 2

The device normalises to the reference current, so where the two CT ratios differ the same per-unit value is a different number of secondary amps at each end. That difference is the ratio matching working, not an error.

Charging current

A line draws capacitive current in at both ends and returns none, so the differential sees it as a genuine internal current. Here it is 0.0417 pu — on a cable of any length that is a real fraction of the threshold, and compensation is not optional. The value entered in DIGSI should come from the commissioning measurement of the energised line, not from a calculation: energise from one end with the far end open and read the current.

The protection interface is protection

Propagation delay, path asymmetry and the synchronisation method are not infrastructure supporting the scheme; on a differential they are part of it. Ping-pong synchronisation assumes the path is symmetric in both directions, and over a multiplexed network a rerouted circuit can break that assumption silently — the asymmetry then lands directly in the differential as a phase error. Record the measured asymmetry at commissioning so there is a baseline to compare against later.

What this tool does not do

  • Synchronise two test sets. That is a GPS or IRIG-B arrangement between the stations. The tool gives both ends' values and says which belong to the remote set; making them coincide in time is the test engineer's problem.
  • Multi-terminal lines. Everything here is two-ended. A three-terminal scheme adds a third current to every sum and a third staging problem.
  • CFC logic and 74TC beyond a checklist. The first is scheme-specific, the second is DC continuity at the terminal block.
  • Setting-file import. Settings are entered by hand, which means they get read off both devices once and checked against each other.

Before the first use on a job

  • Compare the two ends' CT ratios and star-point directions before anything else. A disagreement there makes every differential result meaningless and is the commonest reason a new scheme trips on its first external fault.
  • Decide the staging honestly and write it on the record. A local-end test that is reported as an 87L test is worse than no test, because it reads as proven.
  • Run the through-current stability point before any threshold. It proves ratio, polarity and the sign convention across the interface in one shot, and if it fails nothing else in the table is worth measuring yet.
  • Measure the charging current on the energised line and compare it with what is set.
